## Non-Negotiable Invariants

1. **Continuous Doc API & OpenAPI Maintenance**: The [`.ai/doc-api.md`](.ai/doc-api.md) file and OpenAPI 3.1 specification (`api/openapi/openapi.yaml`) MUST be kept updated on **every code change or addition**, regardless of how small the modification is, if any endpoint, schema, Protobuf contract, Kafka payload, ClickHouse table, or S3 Parquet metadata contract is touched.
2. **Secured Logging**: All logging must be structured JSON (`log/slog`). Strictly redact PII/PHI, client `Authorization` headers, bearer tokens, Kafka SASL/TLS credentials, ClickHouse passwords, AWS IAM/KMS credentials, internal DSNs/paths, and unredacted compliance payloads before emission.
3. **Dual-Track Ingestion Isolation**: Structurally separate compliance access/mutation events (`audit-compliance-records` Kafka topic $\rightarrow$ `rag-telemetry-audit-daemon`) from high-cardinality diagnostic spans (OpenTelemetry Collector $\rightarrow$ `rag-trace-collector-worker`). Never ingest diagnostic waterfalls into the compliance daemon.
4. **Cloud-Native Immutability & Partition-Scoped Monotonic Sequencing**: Use AWS S3 Object Lock in **Compliance Mode** (7-year retention, KMS CMK, CloudTrail data events) instead of application-level Merkle trees. Enforce strict per-stream monotonically increasing sequence IDs (`[min_seq, max_seq]`) scoped by `(producer_id, tenant_id, kafka_partition)` so monotonicity and gap tracking are independent for each producer within a tenant partition, committing Kafka offsets **only after** ClickHouse RowBinary and S3 WORM Parquet persistence succeed.
5. **Amortized Memory Management & NVMe WAL Spillover**: Use `sync.Pool` reusable byte slices (`pkg/pool/byte_pool.go`) and operate directly on `[]byte` in `pkg/redaction/` ($\le 128\text{ B/op}$). On ClickHouse/S3 outages, spill to local NVMe `mmap_wal` (`5 GiB` upper bound) so container RSS stays $\le 1.5\text{ GiB}$ within `1 GiB` request / `2 GiB` limit pods (`GOMEMLIMIT=1800MiB`, `GOGC=80`).
6. **Caller-Side Graceful Degradation (`pkg/auditclient`)**: Read-plane audits use non-blocking buffers (shedding non-essential metadata at $90\%$ fill); write-plane audits enforce synchronous `acks=all` queueing and fail closed (`HTTP 503`) if Kafka is unavailable. Diagnostic channels safely drop spans under duress.
7. **Code Cleanliness & Quality Gates**: All Go code must pass `gofmt -s`, `go vet`, `golangci-lint`, `govulncheck`, `gosec`, `-race` unit/integration tests, and `-benchmem` redaction allocation checks.

## Git Commit Standards

- **Git Commit Frequency**: Commit code as you build. Every working session or phase must contain **at least two git commits**.
- **Conventional Commit Patterns**: All git commit messages must strictly adhere to the following prefixes:
  - `feat:` for new features
  - `fix:` for bug fixes
  - `refactor:` for code refactoring
  - `docs:` for documentation updates
  - `tests:` for tests addition and modification
  - `chore:` for maintenance tasks and environment setup

---

## Pre-Commit Verification Rules

Before committing code, submitting changes, or marking a task complete:

1. Run Go formatting: `gofmt -s -w .`.
2. Run Go static analysis: `go vet ./...` and `golangci-lint run`.
3. Run test suites & allocation benchmarks: `go test -v -race ./...` (applicable during Phase 1 and beyond), and `go test -run=^$ -bench=. -benchmem ./pkg/redaction/...` (skipped until `pkg/redaction` exists, then required in all subsequent commits).
4. Verify [`.ai/doc-api.md`](.ai/doc-api.md) and `api/openapi/openapi.yaml` are updated with all API, schema, proto, or storage contract modifications.
5. Verify Secured Logging rules: Ensure no `fmt.Print*`, bearer tokens, auth headers, credentials, DSNs, or unredacted PII/PHI are logged.
6. Update [`.ai/progress-tracker.md`](.ai/progress-tracker.md).
